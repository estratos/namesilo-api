# NameSilo API Bundle v1.1.0

**Release date:** 2026-10-24

First functional release. The published `1.0.0` was a skeleton: the classes registered by the extension did not exist and the Symfony container could not compile.

## Highlights

- Full implementation of the 7 `estratos/domain-api-interface` contracts (23 methods).
- HTTP client with JSON/XML, timeout, exponential-backoff retries, API key masking, PSR-6 cache and sandbox mode.
- `ResponseMapper` for the 11 contract DTOs.
- 13 domain, DNS, contact, privacy and lock events.
- Centralized error handling with `ApiExceptionFactory` and `ApiException::getApiCode()`.
- Test suite and PHPStan level `max`.

## Added

- `NameSiloClient`, `ResponseMapper` and the 7 contract services:
  - `DomainService`
  - `DNSService`
  - `ContactService`
  - `AccountService`
  - `PrivacyService`
  - `LockService`
  - `NameServerService`
- 13 event classes with dispatching controlled by `events_to_dispatch`.
- `ApiExceptionFactory` to translate NameSilo numeric codes.
- Unit and integration tests with `MockHttpClient`.
- PHPUnit, PHPStan, PHP-CS-Fixer and technical documentation in `docs/`.

## Changed

- The package name is now aligned with Packagist: `estratos/namesilo-api`.
- Service wiring is centralized in `services.php`, with services registered by FQCN and exposed through contract aliases.
- `composer.json` adds `symfony/cache` and `psr/cache`; `ext-simplexml` is suggested for XML responses.
- README and documentation now reflect the actual state.

## Fixed

- `NameSiloBundle` is now in `src/NameSiloBundle.php` and complies with PSR-4.
- `getContainerExtension()` explicitly returns `NameSiloExtension` (required on Symfony 7.4).
- Fixed the invalid `->example(30)` configuration example.
- Fixed contact mapping (`cp`, `ad2`, `fx`) and DNS mapping (`rrdistance`, SRV `weight:port:target`).
- Normalized top-level TLD price keys to the `.tld` form used by `PriceList::getPrice()`.
- Added an `active` status fallback for `listDomains` / `listDomainsByExpirationDate`, whose payloads omit `status`.
- Transport errors no longer include the API key in exception messages.
- Removed duplicate service definitions and overlapping aliases.

## Removed

- `src/Resources/config/services.yaml` (belonged to another project and was never loaded).
- `src/Service/RequestService.php` (legacy class with an old namespace and cURL).

## Breaking changes

- **Package name:** from `estratos/namesilo-bundle` to `estratos/namesilo-api`.
- **`RequestService` removed:** use `NameSiloClientInterface`.
- The `namesilo.*` service IDs remain as aliases, but the primary definitions use each class FQCN.
- The `Estratos\NameSiloBundle` namespace is unchanged; `config/bundles.php` stays the same.

### Upgrade

```bash
composer remove estratos/namesilo-bundle
composer require estratos/namesilo-api:^1.1
```

If you added a VCS entry for `estratos/namesilo-bundle`, remove it.

## Verification

- 32 tests, 120 assertions, OK.
- PHPStan `max` with no errors.
- Symfony container compiled in the integration test.
- `composer validate` passes.
- `php -l` passes for `src/` and `tests/`.
- Read-only flows validated against the production API on 2026-10-24: balance, prices, domains, contacts, availability and domain info.

## Known limitations

- Tests use mocks; read-only flows were validated against the production API, but mutation flows and the NameSilo sandbox still need validation.
- The `ApiResponseCode`, `DomainStatus`, `LockStatus` and `PrivacyStatus` enums are not used in the main flow.
- Some DTO fields are derived or defaulted (`orderId`, `updatedAt`, `available`, `reserved`, `creditLimit`).
- `isDefault` on contacts is ignored with a warning.
- Pagination for `listDomains` and a possible N+1 in `DomainSummary` still need review.
